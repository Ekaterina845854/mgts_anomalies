# Данные

Положите шесть исходных файлов в этот каталог: `data/1.csv` … `data/6.csv`. В Git они не хранятся.
Список файлов задаётся в `src/config.py` → `DEFAULT_CONFIG["data"]["files"]`.

## Входная схема (фактически обнаруженная)

| столбец | тип | где есть | примечание |
|---|---|---|---|
| `dts_id` | строка | все | UUID прибора; в 5.csv — `mapping_ch02` |
| `channel_id` | целое | все | 1 или 2; в каждом файле один канал |
| `timestamp` | `YYYY-MM-DD HH:MM:SS±HH` | все | 1.csv, 6.csv — `+03`; 2–4 — `+00`; 5.csv — без пояса |
| `points` | JSON `[[x, value], …]` | все | x от 0 с постоянным шагом |
| `points_size` | целое | 1.csv, 6.csv | везде совпадает с фактической длиной; при отсутствии вычисляется |

Поддерживается только реально обнаруженный формат `points` (JSON). Строки, которые не разбираются,
отбраковываются с указанием причины (`artifacts/processed/*.issues.csv`, отчёт на странице «Данные и ограничения»).

## Разметка

`labels/labels.csv` — экспертная разметка (изначально пустая, только заголовок):

```
label_id,source_id,start_time,end_time,x_start,x_end,label,annotator,comment,event_id
```

* `label` ∈ {`аномалия`, `норма`, `неопределённо`};
* время — ISO 8601 с поясом (UTC), `source_id` — имя файла без `.csv`;
* метки можно добавлять в интерфейсе («События» → карточка события → «Разметка эксперта»).

P/R/F1 считаются только при наличии хотя бы одной метки `аномалия`.
