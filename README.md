# Fiber Analytics — события в данных распределённых оптоволоконных сенсоров

MVP для хакатона МГТС «Телеком будущего». Проект проходит весь путь от шести исходных CSV до интерфейса:

**валидация → нормализация → признаки → три детектора + экспериментальный автоэнкодер → события → закономерности → сравнение методов → Streamlit**.

## Быстрый старт

Проверено на Windows 11 и Python 3.12.8.

```bash
# 1. окружение
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

# 2. данные: положить 1.csv … 6.csv в data/  (см. data/README.md)

# 3. расчёт (≈60 с на разбор CSV при первом запуске, затем ≈150 с на весь пайплайн;
#    без автоэнкодера ≈70 с: {"detectors": {"autoencoder": {"enabled": false}}})
python -m src.pipeline

# 4. интерфейс
streamlit run app.py              # http://localhost:8501

# 5. тесты
python -m pytest -q
```

Дополнительно:

* EDA: `python -m src.eda` (таблица и графики в `docs/eda/`) или ноутбук `notebooks/eda.ipynb`;
* запуск без синтетического теста: `python -m src.pipeline --no-synthetic`;
* свои параметры: `python -m src.pipeline --config my.json`, где `my.json` содержит только переопределения
  (например, `{"detectors": {"statistical": {"min_threshold": 5}}}`). Параметры также можно менять
  в интерфейсе: «Данные и ограничения» → «Параметры и пересчёт».

## Архитектура

Отдельный HTTP-бэкенд не нужен. Расчёт выполняется офлайн одной командой, интерфейс читает готовые результаты
(Streamlit + независимые модули). FastAPI добавил бы второй процесс и сериализацию, но ничего не дал бы для демо.

```
data/*.csv
  └─ src/data_loader.py   CSV → SourceData (проверка схемы, JSON-разбор points без eval, время/пояс,
                          дубликаты, −300, укороченные профили; причины отбраковки сохраняются)
  └─ src/preprocess.py    → Prepared: бины ≈1 м, сегменты по разрывам, разбиение 60/20/20 по времени,
                          локальная норма (медиана прошлых кадров за 60 мин), общий сдвиг кадра, шум MAD
  └─ src/features.py      признаки окон «кадр × бин»
  └─ src/detectors.py     A — статистический (median/MAD), B — Isolation Forest, общий формат и порог
  └─ src/regression.py    C — Ridge-прогноз + остатки, MAE/RMSE
  └─ src/autoencoder.py   D — автоэнкодер на патчах «5 кадров × 7 бинов», ошибка восстановления
  └─ src/events.py        срабатывания → события (связные области с допусками) + характеристики и категории
  └─ src/patterns.py      повторы, периодичность, синхронность, совпадения между приборами, DBSCAN
  └─ src/evaluation.py    сравнение, совпадения, P/R/F1 по разметке, синтетический тест
  └─ src/repository.py    запись и чтение artifacts/results
  └─ src/pipeline.py      оркестрация, логи (logs/pipeline.log), манифест запуска
app.py + ui/              интерфейс (только чтение результатов, без логики детекции)
tests/                    pytest на синтетических данных
```

* **Кэширование.** Разобранные CSV хранятся в `artifacts/processed/`. Ключ кэша — отпечаток файла и настройки
  загрузки. Повторный запуск не перечитывает CSV: загрузка занимает 1 с вместо 60. В интерфейсе стоит
  `st.cache_data` с ключом по времени изменения манифеста, поэтому смена фильтров не запускает пересчёт.
* **Надёжность.** Расчёт пишется в `results_staging/` и заменяет `results/` только после успешного завершения.
  Ошибка сохраняется в `artifacts/last_failed_run.json`, предыдущие результаты остаются доступны. Ошибка одного
  файла или детектора не останавливает остальные.
* **Воспроизводимость.** `random_state` фиксирован. Конфигурация, её хэш, отпечатки данных и версии библиотек
  записываются в `run_manifest.json`. Повторный запуск даёт идентичный каталог событий (проверено тестом).

## Контракт события (`artifacts/results/events.parquet`, `events.csv`)

| поле | описание |
|---|---|
| `event_id` | `<A/B/C/D>-<источник>-<NNNN>`, например `A-4-0006` |
| `event_date`, `start_time`, `end_time`, `peak_time` | дата — в локальном поясе источника; время — UTC |
| `dts_id`, `channel_id`, `source_id` | прибор, канал, файл |
| `cable_id`, `cable_note` | всегда `null` / «кабель не сопоставлен» (соответствие не предоставлено) |
| `x_start`, `x_end`, `x_peak`, `width_x`, `x_unit` | участок вдоль волокна; единицы (м предположительно / индекс) |
| `anomaly_score`, `anomaly_score_mean`, `threshold`, `anomaly_score_norm` | пиковая и средняя оценка в шкале метода, порог, оценка/порог |
| `detector`, `detector_label` | `statistical` / `isolation_forest` / `regression` / `autoencoder` |
| `duration_s`, `n_cells`, `n_frames`, `n_bins` | размер события |
| `amplitude`, `amplitude_z`, `direction` | максимальное отклонение от нормы (в единицах сигнала и в σ) |
| `pre_level`, `post_level`, `step_shift`, `rise_time_s`, `abrupt`, `persistent` | контекст до и после события |
| `shape`, `duration_class`, `extent_class`, `repetition_class`, `event_type`, `type_confidence` | описательные категории |
| `repeat_group`, `repeat_count`, `sync_group`, `sync_size`, `cluster`, `pattern_tags` | закономерности |
| `split` | train / validation / test (по кадру начала события) |
| `features`, `labels` | сводка признаков окна (JSON), метки (JSON-список) |

Проверка контракта (`events.validate_event_frame`) выполняется в пайплайне и в тестах.

## Детекторы и параметры (`src/config.py`)

Все методы работают на одной сетке окон «кадр × бин» и возвращают оценки в одном формате: чем больше, тем
необычнее; NaN — окно не оценивалось из-за нехватки истории.

| | A. Статистический | B. Isolation Forest | C. Регрессия + остатки | D. Автоэнкодер |
|---|---|---|---|---|
| вход | отклонение бина от медианы его прошлых кадров (60 мин) минус общий сдвиг кадра | 8 признаков: z, \|z\|, скорость, контраст с соседями, разброс внутри бина, std за 5 кадров, длительность, ширина | v[t]−v[t−1] по d1, d2, возврату к норме, сдвигу соседних бинов другой чётности, соседям, dt | патч z: текущий и 4 прошлых кадра × бин ±3 (35 значений), без будущего |
| обучение | MAD шума на train | 150 деревьев, max_samples 512, 60 тыс. окон train | Ridge (α=1) на train | MLP 35→24→6→24→35 (tanh, sklearn), 40 тыс. патчей train без 1 % самых экстремальных |
| оценка | \|dev\| / (1.4826·MAD) | −score_samples (инверсия шкалы sklearn) | \|остаток\| / (1.4826·MAD остатков) | (ошибка восстановления центра − медиана) / (1.4826·MAD) на train |
| порог | 6σ, фиксированный | квантиль 99.8 % на validation, не ниже 0.6 | 6σ, фиксированный | 6σ, фиксированный |

Автоэнкодер сделан на `sklearn.neural_network.MLPRegressor`, а не на PyTorch: для 35-мерного входа этого достаточно,
и не нужна тяжёлая зависимость. Это дополнительный эксперимент: архитектура не подбиралась. Отключается
флагом `detectors.autoencoder.enabled` или галочкой на странице «Данные и ограничения».

Почему пороги разные. В validation 1.csv идут крупные реальные изменения: квантиль 99.8 % дал бы для A порог
около 31σ и пропустил бы всё умеренное. У IF шкалы в σ нет, поэтому для него берётся квантиль. Для всех методов
сохраняется доля срабатываний на validation — это контроль ложных тревог.

**События.** Срабатывания одного канала и сегмента объединяются при разрыве ≤ 300 с и ≤ 2 бинов. Одиночное окно
становится событием только при оценке ≥ 1.5 × порог. Категории (порог длительности 600 с, протяжённости 5 ед.,
доля резкого скачка 0.6, критерий последействия 3σ) описывают форму сигнала, а не причину.

## Результаты на реальных данных

Последний запуск: 1750 событий (всего по четырём методам). Сравнение — на test-части каждого источника
(последние 20 % кадров, всего 21.5 ч).

| метод | событий | в час | совпали с другими | уникальные | найдены всеми методами | срабатываний на validation | время, с | пик памяти, МБ |
|---|---|---|---|---|---|---|---|---|
| A. Статистический | 42 | 1.95 | 16 | 26 | 8 | 1.91 % | 0.01 | 11 |
| B. Isolation Forest | 112 | 5.20 | 15 | 97 | 8 | 0.20 % | 42.6 | 97 |
| C. Регрессия | 16 | 0.74 | 12 | 4 | 8 | 0.24 % | 1.6 | 128 |
| D. Автоэнкодер | 35 | 1.63 | 19 | 16 | 8 | 0.74 % | 67.8 | 59 |

* **Precision / Recall / F1 не вычислены: экспертной разметки нет.** Интерфейс так и пишет и не показывает нули. Метки можно добавлять в карточке события; после пересчёта метрики появятся автоматически.
* **Регрессия (MAE / RMSE на test, единицы сигнала).** На источниках 2–6 модель лучше наивного прогноза
  «как в прошлом кадре»: например, 0.151 / 0.192 против 0.188 / 0.239 на файле 2 и 0.377 / 0.474 против
  0.511 / 0.642 на файле 5. На файле 1 модель **не лучше** наивного прогноза (0.238 / 0.345 против
  0.235 / 0.341): там преобладают одновременные изменения многих участков.
* **Синтетический тест** (копия 3.csv, 40 внесённых отклонений в test-часть) — только проверка работоспособности,
  а не качества на реальных аномалиях. Recall:

  | амплитуда | n | A | B | C | D |
  |---|---|---|---|---|---|
  | < 6σ | 5 | 0.20 | 0.20 | 0.20 | 0.20 |
  | 6–10σ | 11 | 1.00 | 0.09 | 0.64 | 0.82 |
  | ≥ 10σ | 24 | 1.00 | 0.79 | 1.00 | 1.00 |

  У IF на этом источнике порог по квантилю высокий (0.80): validation 3.csv содержит крупные изменения. Это
  ограничение квантильного порога.
* Методы находят во многом разные события: на уровне окон коэффициент Жаккара 0.05–0.21. Ближе всего
  автоэнкодер и статистический метод (0.21): оба опираются на отклонение от локальной нормы. Уникальная находка —
  не обязательно ложная тревога; примеры показаны на экране «Сравнение методов» → «Примеры находок».

## Интерфейс

| экран | что показывает |
|---|---|
| Итоги | статус последнего расчёта, ключевые числа, самые заметные события, уровни внимания, события во времени, кнопка «Показать пример» |
| События | каталог с понятными названиями и уровнем внимания, карточка события (что, где, насколько необычно, другие методы, график, возможная причина, разметка); вкладки «Карта сигналов» (тепловая карта «время × координата») и «Технический каталог» со всеми полями и фильтрами |
| Закономерности | типы и признаки событий, прозрачные правила, кластеры DBSCAN, повторы, автокорреляция, совпадения между приборами; пространственный обзор вдоль волокна |
| Сравнение методов | карточки методов A–D, совпадения и уникальные находки, Жаккар, наложение событий, MAE/RMSE, синтетический тест, экспорт |
| Данные и ограничения | методы, источники и качество данных, параметры и пересчёт, ограничения |

**Уровень внимания** — приоритет просмотра, а не оценка опасности. Шкалы методов несопоставимы, поэтому
оценка/порог и |z| ранжируются внутри каждого метода и смешиваются с числом совпавших методов
(веса 0.4 / 0.3 / 0.3). Высокий — верхние 20 % событий, средний — следующие 30 %, остальные — низкий
(`HIGH_SHARE`, `MEDIUM_SHARE` в `ui/presentation.py`).
